The Pages site had been frozen for 11 days, because of a private submodule

  • Cause: jay, with a phone screenshot of docs/features/README.md rendered in the GitHub app: "the feature designs card on index page does not show the real content like this". The card on alice's landing page opens linked0.github.io/rabbit/html/docs/features/README.html, and that page was serving something smaller and older than the file on disk — 25,922 bytes against 49,688.
  • Reasoning: the card was fine and the generated HTML was fine; both were committed and pushed. The Pages build was the thing that had stopped. Every build since 2026-09-11 had the status errored with the unhelpful message "Page build failed", so the site kept serving the last successful copy — eleven days of edits, invisible. The cause is that the legacy Pages builder clones the repository with its submodules, and games/jayverse-game is a private repository it cannot authenticate to. Nothing about the failure mentions submodules, which is why it sat unnoticed; the only visible symptom was content that quietly stopped changing. Note that .nojekyll would not have fixed it — the submodule fetch happens during checkout, before Jekyll ever runs.
  • Change: .github/workflows/pages.yml publishes docs/ through Actions instead, with actions/checkout at its default submodules: false — the whole fix is not asking for something that was never needed to publish docs. Jekyll was dropped with it, deliberately: every .md in the repo is already rendered to docs/html/ by scripts/generate-docs-html.mjs, and every link in the site points at that output, so Jekyll was doing no useful work while being one more thing that could break. docs/.nojekyll makes that explicit. The Pages source was switched from the legacy builder to build_type: workflow.
  • Result: the workflow ran green and the features page is 49,245 bytes with the "Three end-to-end scenarios" section and the rails-shortlist link present, matching the source. All four rabbit-backed cards on alice's index (Feature Designs, Current Plan, History, Docs) return 200 with current content, and today's three history entries now appear in the live history index. Alternatives not taken, both jay's call: make jayverse-game public, or drop the submodule from this repo.

The game leaves the repo: submodule out, own host in

  • Cause: after the Pages fix above, jay chose the alternative it had left open: "서브모듈을 이 저장소에서 빼고 game top menu를 없애고 다른 서비스처럼 game.jaylabs.xyz로 접근할수 있도록 처리해줘".
  • Reasoning: the submodule existed so the portal could iframe a static build of the game at /game, since the game is Next 16 / React 19 and the portal is Next 14 / React 18. Hosting the game on its own domain removes the reason for all of it at once — the submodule, the game:build script, the public/jayverse-game/ bundle, the two next.config.js rewrites that mapped extensionless paths onto it, and the middleware exemptions that kept auth off its assets. Worth recording what was found on the way: the portal chip pointed at burrow.jaylabs.xyz, which does not exist in the DNS zone at all — that chip had been a dead link, not a working one being moved. Firebase Hosting was chosen over Cloud Run because defi.jaylabs.xyz → jayverse-defi.web.app and verex.jaylabs.xyz → verex-499205.web.app already work that way and the game is a static export; following the house pattern beats inventing a second one. cleanUrls matters: the Next export writes street.html, so without it every route but / 404s — which is precisely what the removed next.config.js rewrites had been doing for the embedded copy.
  • Change: submodule games/jayverse-game and .gitmodules removed; app/game/ deleted; public/jayverse-game/ and scripts/build-game.mjs deleted; game:build dropped from package.json; the GAME entry removed from app/Nav.tsx; /game and /jayverse-game removed from middleware's PUBLIC_PATHS and the matcher exemption; lib/jayverse.ts now points the chip at https://game.jaylabs.xyz. On the hosting side: Firebase site jayverse-game created in doubletree-498007, the static export deployed through the Hosting REST API with cleanUrls and trailingSlashBehavior: REMOVE, and game.jaylabs.xyz registered as a custom domain with its CNAME and _acme-challenge TXT added to the jaylabs-xyz Cloud DNS zone.
  • Result: pnpm build passes with no /game route and no GAME entry in the nav. jayverse-game.web.app serves /, /street and /settlement at 200 and a missing path at a real 404. The custom domain's certificate was still validating at the time of writing. A side effect worth having: the Pages build no longer depends on a private submodule at all, so the class of failure fixed above cannot recur through this route.

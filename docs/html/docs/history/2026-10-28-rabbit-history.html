Jay Chat: scroll to the new question, follow the answer only from the bottom

Cause: jay (screenshot): clicking a suggested question did not scroll the chat box down, so the new turn stayed out of sight. Reasoning: The old code scrolled only inside the stream loop, right after setMessages, which is before React draws the new text. It always landed one chunk short, and it never scrolled when the question itself was added. Scrolling in a useEffect after the render measures the real height. Following the stream unconditionally would yank a reader who has scrolled up, so it sticks only when the reader is within 80 px of the bottom. Change: app/JayChatClient.tsx: useEffect on messages. A new turn always scrolls the log to the bottom and scrollIntoView({block: "nearest"}) brings the chat box on screen; while streaming, it scrolls only if stickRef is set (updated by onScroll). The per-chunk scrollTo is gone. Branch claude/chat-autoscroll. Result: Playwright on :3100 (Sonnet), three suggestion clicks: the log is at the bottom (gap 0 px) right after each click and after each answer, and the newest message is on screen. Scrolling to the top mid-answer stays at the top (scrollTop 0 after the answer ends). Not deployed. The fix is provider-independent and ships with the next deploy.

jayverse-game

A read-only renderer of the autonomous payment agent's journal in a 3D market street. On each tick the agent character walks to a market board and acts out that journal row — a buy (fill pulse + board nudge), a refusal (a labeled red barrier naming why), or the most common case, nothing (a glance, then walk on). Nothing is signed; the game never drives the agent and never moves money.

Design doc (authoritative): ../rabbit/docs/features/jayverse-game.md

This is the Weekend MVP from that doc: one flat street, ~6 boards, one agent, replay mode only, driven by a bundled sample journal — no live backend needed.

Stack

  • Next.js 16 (App Router) + TypeScript, pnpm
  • react-three-fiber (@react-three/fiber 9) + @react-three/drei 10 + three 0.180
  • Only primitive geometry (planes/boxes/capsules/rings) + a CanvasTexture board face + drei <Text> for barrier labels. Zero downloaded 3D assets — runs offline.

Run

pnpm install
pnpm dev      # http://localhost:3000  (open /street, or click through from /)
# or
pnpm build && pnpm start
  • / — landing page, "Watch the agent →"
  • /street — the 3D replay. Lazy-loaded via dynamic(() => import(...), { ssr:false }) so three.js never runs on the server.

Controls

  • Play / Pause, step back / forward (⏮ ⏭), speed (cycles 1×–4×)
  • Drag the timeline to seek to any tick
  • Orbit the scene with the mouse (spectator camera)
  • The journal panel (right) shows the current tick: action, fill or refusal reason, cited evidence, the board quote, and a note — synced to the scrubber.

The scrubber advances through discrete ticks, but the agent animates smoothly between them at 60fps (a continuous playhead in a ref, advanced in a rAF loop, decoupled from React renders). Data cadence ≠ render cadence.

Sample-journal schema

Types live in lib/journal.ts; the bundled run is data/sample-journal.json. This is the shape a GET /api/agent/journal?run=<id> response would return (see "Deferred" below).

Journal {
  runId: string
  startedAt: string            // ISO 8601
  budget: { currency, total, remaining }
  markets: Market[]            // distinct boards, in street order
  ticks: Tick[]
}

Market { id: string; title: string }

Tick {
  id: number                   // monotonic; also its index in the run
  market: Market               // which board the agent visited
  action: "buy" | "none" | "refused"
  fill?: { side: "YES"|"NO"; size: number; price: number }   // iff buy
  reason?: RefusalReason                                       // iff refused
  evidence?: { headline: string; source: string }            // optional
  quote: { bid: number; ask: number; last: number }           // board quote @ tick
  note?: string
}

RefusalReason =
  "budget_exhausted" | "expired" | "no_evidence"
  | "position_limit" | "market_closed" | "cooldown"

The sample run has 22 ticks: 14 none, 3 buy, 5 refused (5 distinct reasons), mirroring the console's "most ticks did nothing / the refusals look different" point. Tick 20 notes the mandate window has elapsed; tick 21 is a refusal after expiry (reason: "expired") on a strong late signal — nobody revoked it, the clock did.

Stubbed / deferred (not in this MVP)

  • Live (synchronous) delta-polling mode — ?since=<cursor> polling of the running agent. The doc lists the exact live API shape as an open question (§7 #2), so only the type + a bundled ?run= sample ship here. Replay is the deterministic, zero-dependency demo path.
  • All six refusal visuals — the type supports six reasons and the sample exercises five; each renders the same barrier prefab with a different label rather than six bespoke prefabs.
  • Real city assets — primitives only (no glTF kit, no draco, no skybox, no baked lighting, no sparkline-on-canvas beyond the quote cells).
  • Follow-cam — MVP uses a free spectator orbit; the doc leans follow-cam with optional free-look (open question #1).
  • Player-trading layer — explicitly out of v1 (spectator-first, read-only: no wallet, no signing). A later optional mode per the doc.
  • Portal integration (Rabbit /game card, auth/session) and board-quote streaming from the Verex API are also later work.

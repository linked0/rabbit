### PoC 카드 추가: 암호화 멤풀 — "암호화가 가리지 못하는 것"

**Cause:** jay가 이더리움 개발자들의 멤풀 암호화 논의 기사를 붙여넣고 PoC 항목 추가를 지시. 커밋/머지 지시는 없었다.

**Reasoning:** 기사는 **"개발자들이 19일 회의를 열어 논의할 예정"**, **"현재 알려진 기술 중 이더리움 규모를 만족하는 건 없다"**로 읽힌다. 검증해 보니 뒤쪽은 맞고 앞쪽은 정확하지 않다 — **이미 경합하는 초안이 두 건 테이블에 있다**: 기술 중립적 키 제공자 층을 프로토콜에 심는 **EIP-8105**, 빌더가 내용을 읽기 전에 봉인 페이로드에 커밋하게 하는 **EIP-8184(LUCID)**. 즉 설계 공간은 "할 것인가"가 아니라 **"어떤 실패를 받아들일 것인가"**다.

그리고 검증 과정에서 카드의 뼈대가 나왔다. **EIP-8105 의 봉투는 설계상 평문이다** — 체인 ID, 논스, 우선/최대 수수료, 가스량, 키 제공자 ID, 키 ID, **서명 성분**(→ 발신자 복원 가능). 이더리움 자신의 패턴 문서가 귀결을 그대로 적어 둔다: *"크기·가스 한도·발신자 주소는 복호화 전에도 보이며, 크거나 식별 가능한 거래에 대한 추론 공격을 여전히 가능하게 한다."* **샌드위치 봇은 calldata 가 아니라 "큰 거래가 온다 + 대략 얼마다"만 알면 된다.** 그래서 카드의 질문을 "암호화가 되는가"가 아니라 **"남은 메타데이터가 추출 이익의 몇 %를 여전히 먹여 살리는가"**로 잡았다 — 만들거나 측정해서 답할 수 있는 형태여야 한다는 이 카탈로그의 규칙에 맞춘 것.

기존 라이브 `pbs` 카드에 덧붙이는 것도 검토했으나 기각했다. `pbs` 는 **이미 출시된 데모**(서처 번들 제출 + 릴레이 관측)라 미착수 연구 항목을 붙이면 상태가 섞인다. 대신 배치로 관계를 표현했다 — `senpi-harness` 와 `price-at-a-moment` 사이. `price-at-a-moment` 와는 **같은 창(window)을 다른 쪽에서 본다**(저쪽: 정산 시점 가격 하나를 무검증으로 믿음 / 이쪽: 체결 전 구간에 무엇이 보이는가), `pbs` 와는 **같은 시장의 추출 쪽 대 방어 쪽**이다.

**Change:** `lib/poc-cards.ts` 에 `encrypted-mempool` 카드 추가(`status: "soon"`, `date` 없음 — 신규 항목 기본값 규칙). 작업 항목 셋을 싼 순서로: **① 잔여 MEV 재현**(과거 블록을 EIP-8105 평문 필드만으로 깎아 샌드위치 대상 선별 → 실제 추출분 대비 채점, 라벨링은 `pbs` 가 만든 릴레이 배관 재사용), **② 두 블록짜리 청구서**(봉투 실행/페이로드 실행이 서로 다른 블록 + 복호화 실패해도 수수료 지불 vs 사용 시점 비용 0인 프라이빗 릴레이 — 교차점 거래 규모 모델링), **③ 귀속 불가능한 실패**(제공자 n·임계 k 시뮬레이터로 *보류/조기 유출/단순 지연* 트레이스 생성 → 바깥에서 구별되는가; 구별 안 되면 슬래싱은 물 곳이 없다). `pnpm docs:pocs` 재생성. `docs/index.html` 은 라이브 카드 6개만 싣기 때문에 변동 없음.

**Result:** `npx tsc --noEmit` exit 0. 소스 diff **+26/-0**, 중복 키 0, 렌더링 카드 48 → **49**. 생성 HTML 전수 스윕에서 **신규 이슈 0건**(`docs/index.html` 의 div 28/27 불균형과 `file:///Users/...` 절대링크는 기존 그대로 — 이번 변경과 무관하며 해당 파일은 수정되지 않았다). 카드는 목록 9번(senpi-harness ↔ price-at-a-moment 사이)에 위치. **커밋하지 않고 워킹트리에 둠** — jay의 리뷰 대기.

How the skill works

1

Phase 1 — Extract what's known

Reads the user's input and pulls out: product name, audience, CTA, brand colors, features, sections requested. Identifies what's missing against a checklist (tagline, testimonials, feature details, etc.).

2

Phase 1 — Clarifying questions

Asks one grouped set of 4–8 targeted questions, organized by theme (product, audience, visual style). Waits for answers before writing any code. Skips questions that can be reasonably inferred.

3

Phase 2 — Apple-style code generation

Generates a complete single-file HTML/CSS/JS page following a built-in Apple design system. Outputs to /Users/jay/work/task/. Marks every placeholder with <!-- TODO: Replace with... -->. Reports what it built and what needs replacing.

Built-in Apple design system

Typography

  • Stack: Inter → SF Pro → system → Helvetica
  • Hero headlines: 64–96px, weight 800
  • Letter-spacing: -0.04em to -0.045em
  • Body: 17–19px, line-height 1.65–1.7
  • -webkit-font-smoothing: antialiased

Color system

  • Backgrounds: #ffffff / #fbfbfd / #f5f5f7
  • Primary text: #1d1d1f
  • Secondary text: #6e6e73
  • Accent: user brand color (teal / purple / orange)
  • Borders: #e5e7eb (subtle)

Animations

  • IntersectionObserver scroll reveal
  • Fade-up: opacity 0→1, translateY 28px→0
  • Staggered delays: 0.1s, 0.2s, 0.3s per card
  • Hover: scale(1.02) + shadow lift
  • will-change: transform on interactive elements

Standard sections

  • Sticky frosted-glass nav (backdrop-filter)
  • Full-viewport hero + inline product mockup
  • Customer logo strip
  • Features grid (3–6 cards with hover)
  • How-it-works (numbered steps)
  • Testimonials, Pricing (with toggle), Footer CTA

#86 · IMPORTANT

An RPC response is a view, not consensus

“The chain says” usually means “the node behind this endpoint currently reports.” Those are not equivalent statements.

Why

A second provider improves availability but does not automatically improve correctness. Providers can be stale, disagree about the head, or return the same height with different hashes. An application needs a policy for disagreement, not just round-robin failover.

PoC

Query two independent providers for latest, safe, and finalized block number and hash. Inject stale and conflicting responses. Verify that reads can degrade gracefully while irreversible writes or fulfillment stop when the required confidence cannot be established.

SignalQuestion
AvailabilityDid an endpoint answer?
AgreementDo independent nodes report the same block hash?
CanonicalityIs the receipt still on the selected chain?
FinalityHas the block reached the required confidence tag?

한국어

호스팅 RPC의 응답은 합의 그 자체가 아니라 한 노드가 보는 체인입니다. PoC는 독립 제공자 둘의 latest·safe·finalized 블록 번호와 해시를 비교하고, 오래되거나 충돌하는 응답을 주입해 어떤 작업은 계속하고 어떤 비가역 작업은 중단할지 정책으로 만듭니다.

Reference: Ethereum JSON-RPC API.

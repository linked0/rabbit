🚨 The "Missing Bids" Pattern (Commit 02072b1)

The Pattern: Race condition between data persistence and UI updates. The client refreshes the state before the server has finished writing the new state, leading to "ghosting" where recently created orders (residues) or updated balances don't appear immediately.

1. Server-Side: Synchronization Fix

The broadcast was moved to the very end of the execution flow to ensure the database reflects the new orders before the client re-fetches.

Before (api/src/routes/trade.ts)
// Update maker order
await orderRepository.updateAfterFill(...);

// Broadcast immediately - RACE CONDITION!
wsService.broadcastTradeExecuted(...);

// Save residue LATER
await saveRemainingTakerOrder(...);
After (api/src/routes/trade.ts)
// Update maker order
await orderRepository.updateAfterFill(...);

// 1. Save residue FIRST
await saveRemainingTakerOrder(...);

// 2. Broadcast LAST - UI stays in sync
wsService.broadcastTradeExecuted(...);

2. Client-Side: Full Intent Signing

Ensuring the user signs for their total intended volume, enabling the server to validly create residues as new limit orders.

Before (web/src/hooks/useTrade.ts)
// Sign only for what CAN be matched
const amountToSign = sum(matchingOrders);
const sig = await sign(amountToSign);

signedMakerAmountBI = amountToSign; // $92
After (web/src/hooks/useTrade.ts)
// Sign for FULL user intent
const fullAmount = params.amount;
const sig = await sign(fullAmount);

signedMakerAmountBI = fullAmountBI; // $120

Impact Analysis

  • Consistency: Orders no longer disappear during high-volume "sweeping" trades.
  • Efficiency: Combined with multicall (`execute-batch`), the system stays responsive even when matching dozens of levels.

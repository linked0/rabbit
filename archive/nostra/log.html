🚨 The "Missing Bids" Pattern (Commit 02072b1)

Pattern identified: A recurring issue where limit orders (specifically residues from market-to-limit trades) failed to appear in the UI due to a race condition between database persistence and WebSocket broadcasting.

1. Server-Side: Execution Order (api/src/routes/trade.ts)

Before (Broadcast too early)
// 1. Match on-chain
await tx.wait();
// 2. Broadcast immediately
ws.broadcastTradeExecuted();
// 3. Save residue LATER
await saveRemainingTakerOrder();
After (Synchronized)
// 1. Match on-chain
await tx.wait();
// 2. Save residue FIRST (Block until DB done)
await saveRemainingTakerOrder();
// 3. Broadcast LAST
ws.broadcastTradeExecuted();

2. Client-Side: Full Intent Signing (web/src/hooks/useTrade.ts)

Before (Match-only signing)
// signedMakerAmount = matchable sum
signedMakerAmountBI = matchingSum; // $92
// Server cannot create remainder order
After (Full intent signing)
// signedMakerAmount = full user intent
signedMakerAmountBI = fullRequestBI; // $120
// Server creates $28 residue order

Impact

  • Eliminated the "missing bids" ghosting effect during heavy trading.
  • Enabled atomic "Sweep then Bid" behavior in a single transaction/signature flow.

2025-12-23 (Market-to-Limit Residue Order Fix)

Problem

On the detail page, after a $120 market buy that only matched $92 of liquidity, the remaining $28 should have become a 60¢ limit bid in the order book. However, the bid was not appearing.

Root Cause Analysis

In useTrade.ts, the taker order was being signed for only the matchable amount ($92), not the user's full intent ($120).

Before (Bug)
// totalTakerAmountBI = sum of what CAN be matched ($92)
const totalTakerAmountBI = orderPairsToSign.reduce(
  (sum, p) => sum + p.usdcAmountBI, BigInt(0)
);

// Signed order uses only matchable amount
signedMakerAmountBI = totalTakerAmountBI; // $92, not $120!
After (Fix)
// Parse the user's FULL intended amount
const fullAmountBI = ethers.parseUnits(params.amount, 6);

// Sign for full intent - residue becomes limit order
signedMakerAmountBI = fullAmountBI; // $120

Why This Caused the Bug

When saveRemainingTakerOrder() ran after the trade:

  • totalMakerAmount = 92 (from takerOrder.makerAmount)
  • totalTakerFillAmount = 92 (sum of all fills)
  • remainingMakerAmount = 92 - 92 = 0

Since remainingMakerAmount was 0, the function returned early without creating a residue order.

With the Fix

  • totalMakerAmount = 120 (user's full intent)
  • totalTakerFillAmount = 92 (actual fill)
  • remainingMakerAmount = 120 - 92 = 28

Now a $28 limit bid at 60¢ is correctly created.

Files Modified

  • web/src/hooks/useTrade.ts - Changed to sign for full user intent, not just matchable amount

Testing Required

      status: 'OPEN'

    wsService.broadcastOrderBookUpdate(outcomeId);
  }
}

2025-12-16 (Docker Runtime Path & Asset Fixes)

Cloud Run Error (Misleading)

ERROR: container failed to start and listen on the port defined by PORT=8080

Important: This is a generic Cloud Run error that appears whenever the container crashes during startup. It does NOT mean there's a port configuration problem. Check the actual logs to find the real cause.

Issue 1: Module Not Found (revision 00008)

Actual Error: Cannot find module '/app/dist/index.js'

Cause: TypeScript tsconfig.json has "rootDir": "./" which preserves the src/ folder structure in output. Source at src/index.ts compiles to dist/src/index.js, not dist/index.js.

Solution:

  • Dockerfile.api: Changed CMD ["node", "dist/index.js"] → CMD ["node", "dist/src/index.js"]
  • package.json: Changed "start": "node dist/index.js" → "start": "node dist/src/index.js"

Issue 2: Missing ABI Files (revision 00009)

Actual Error: ENOENT: no such file or directory, open '/app/dist/src/abis/CTFExchange.json'

Cause: TypeScript only copies JSON files that are explicitly imported with resolveJsonModule. The src/abis/ folder has 4 JSON files but only 1 was being copied to dist/.

Reason: Code uses fs.readFileSync() to load ABIs at runtime, not static imports. TypeScript doesn't know these files are needed.

Solution:

  • package.json: Changed "build": "tsc" → "build": "tsc && cp -r src/abis dist/src/"

Files Modified

  • Dockerfile.api - Fixed CMD path to dist/src/index.js
  • package.json - Fixed start script path + added ABI copy to build script

Result

Build now produces correct output structure with all required assets. Container should start properly.
